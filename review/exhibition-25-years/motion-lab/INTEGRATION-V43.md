# Исправление походки в реальной выставке · v43

**Исторический протокол v43; недостаточен для общей приёмки движения.** Текущий кандидат, повторные проверки и ограничения описаны в [INTEGRATION-V44.md](INTEGRATION-V44.md). У v43 отсутствовала общая динамическая система избегания посетителей. Дата исходной записи: 22.11.2026, ветка `codex/avatar-motion-lab-20261122`, PR #95. Последующая HTTP-проверка уточнила фактическую цепочку публичной v42: `exhibition-3d.js?v=42` → `visitors-v40.js?v=42`. Публичная версия и версия ветки должны проверяться отдельно.

## Почему предыдущий результат не исправил сайт

Предыдущий PR добавил изолированную лабораторию. Страница выставки продолжала загружать `visitors-v42.js`; выводы эксперимента не были применены к её контроллеру.

Кроме того, точность экспорта старых motion GLB проверяла сохранение уже перенесённой анимации. Она не доказывала правильность самого переноса. У source и target различаются анатомические положения рук в настоящих bind-позах. UPF CURRENT без общей опорной позы сохранял систематическое отклонение направлений рук примерно на 11–19°.

В старом runtime после клипа работали два решателя ног — `plantFoot` и `transitionFoot`. Движение по новому направлению начиналось раньше разворота корпуса. Эти механизмы могли изменять хорошую исходную позу непосредственно в выставке.

Сохранённый процесс проверки движения требовал непрерывного цикла, переходов и нескольких ракурсов. Одни численные результаты экспорта и отдельные удачные кадры не выполняли этот критерий.

## Что изменено

- [Основная страница](../index.html) и [сцена](../exhibition-3d.js) подключают v43. Это интеграция в существующую выставку.
- [Контроллер](../visitors-v43.js) использует фактически пройденное расстояние для фазы Walk, ограничение ускорения и замедление перед остановкой.
- [Обработка движения](../visitor-motion-v43.js) сохраняет позу AnimationMixer. Старые решатели ног не вызываются.
- Обе 13-клиповые библиотеки пересобраны после общей T-позы временных source/target скелетов. Выставочные меши, skin и inverse bind matrices сохранены.
- Добавлены восемь записанных поворотов Microsoft Rocketbox: Left/Right 90°/180° для каждого персонажа. Исходные yaw и XZ извлекаются в holder один раз; авторский угол не подгоняется.
- Маршрут начинается в фактической конечной точке поворота и подходит к экспонату по направлению наблюдения. Это устраняет необходимость завершать путь резким разворотом на месте.
- Контакт с плоским полом корректируется вертикальным смещением отдельной группы всего персонажа, в пределах −30…+35 мм. Суставы не подстраиваются. Исправлен порядок обновления матриц SkinnedMesh перед измерением полного weighted Foot/Toe union.

Происхождение, лицензии, точные версии инструментов и SHA файлов: [ASSET-SOURCES.md](ASSET-SOURCES.md) и [motion assets](../assets/models/visitors/motions/README.md).

## Что проверено

### Перенос и упаковка

Независимое сравнение восьми фаз Walk с исходным скелетом:

| Измерение | Emma | Ethan |
| --- | ---: | ---: |
| Максимальное отклонение направлений рук до исправления | 19,0753° | 18,5975° |
| После общей опорной позы | 0,13794° | 0,02639° |
| Направления бедра/голени после исправления | 0,13491° | 0,03023° |

Упаковка новых библиотек отдельно проверена на 13 клипах × 21 фазе × 80 суставах каждого персонажа. Максимальное отклонение положения суставов менее 0,1 мм; вращений тела — менее 0,013°, пальцев — менее 0,015°. Вспомогательные лицевые суставы доходят до 0,087°. Первоначальный общий диагностический предел 0,05° поэтому **не пройден**; принятие для походки основано на отдельно опубликованных показателях тела и позиции, без переименования старого FAIL в PASS.

Для восьми записанных поворотов проверены направления костей, колени, root yaw и XZ. Полный независимый прогон 141 кадров каждого Left90 подтвердил направления до 0,000064°. Эти проверки точности не заменяют визуальной оценки поведения.

### Реальная сцена: 45 секунд

[Машиночитаемый итог](checks/v43-integrated-gait.json) сохраняет SHA файлов, использованных при проверке, и отдельно SHA Git-блоков. Для index.html и exhibition-3d.js Git меняет только CRLF на LF; побайтовое равенство после этой нормализации проверено. Содержимое кода не изменилось. Размеры окна — 1440×1000 и 390×844; шаг времени 1/60 с; 2701 кадр на каждом размере. Оба персонажа завершили по два маршрута; третий начался в конце интервала.

| Проверка | Результат |
| --- | --- |
| Исключения страницы и console errors | 0 |
| Локальная поза против независимого AnimationMixer | Позиция 0 м; вращение ≤3,82×10⁻⁶° |
| Общее зависание обуви над полом более 2 мм | 0 кадров |
| Максимальное остаточное погружение Emma | 1,5786 мм |
| Максимальное остаточное погружение Ethan | Численный ноль |
| Превышение предела подъёма | Emma: 4 кадра; Ethan: 0 |
| Превышение предела опускания | 0 |
| Совпадение полного shoe union с независимым измерением | ≤1,7×10⁻¹⁶ м |

Строгий gate «ни одного превышения cap» остаётся **FAIL**. Квалифицированная приёмка контакта использует уже заданный допуск 2 мм; предел подъёма не повышен ради прохождения теста. Это ограничение сохранено и в компактном отчёте.

Для контроля поз просмотрены реальные front/side-кадры поворотов и ходьбы. Непрерывная запись маршрутов предназначена для просмотра владельцем: в ней нужно оценивать переходы, ощущение веса и скольжение, а не только положение одной ступни на отдельном кадре.

## Границы результата

- Контакт по минимальной высоте обуви не доказывает отсутствие скольжения. Полный foot locking, ступени и склоны не реализованы.
- Проверка локомоции отключает дополнительные жесты через `visitorDemoEvery=9999`. Художественная приёмка всех 13 жестов не заявлена.
- Детерминированная запись использует реальный renderer и visitor updater, но останавливает фоновый animation loop и продвигает движение фиксированным шагом. Это не измерение FPS телефона.
- Изображения неудачных ранних прогонов с потерянным WebGL-контекстом признаны недействительными и не используются как доказательство.
- Исторические A/B/C, старые 273-позовые и UI-отчёты сохранены в лаборатории с явным указанием, к каким файлам они относятся.

## Воспроизведение

Из корня репозитория, Python с Playwright и установленным Microsoft Edge:

```console
python review/exhibition-25-years/motion-lab/tools/qa_integrated_gait.py --repo . --evidence ../v43-qa-output --seconds 45 --viewports desktop mobile --skip-captures
```

Команда сохраняет строгий диагностический результат; для этого кандидата её ненулевой код завершения ожидаем из-за четырёх превышений cap. Исходный результат не скрывается. Большие telemetry, FBX и видео не входят в Git.

Для повторяемой записи с фиксированным мировым направлением камеры:

```console
python review/exhibition-25-years/motion-lab/tools/record_integrated_gait.py --repo . --reference-report ../v43-qa-output/integrated-gait-report.json --evidence ../v43-video
```

Recorder требует ffmpeg и Pillow, проверяет SHA сцены, здоровье WebGL и непустые кадры. При перезапуске браузера на границах коротких сегментов он сверяет позу со сохранённой непрерывной траекторией; скорость итогового видео — 30 fps при шаге симуляции 1/60 с.

Пересборка поворотов описана в [README](README.md#пересборка-записанных-поворотов). В репозитории находятся небольшой manifest восьми закреплённых FBX, Blender exporter и Node converter; сами исходные FBX скачиваются по manifest.

Публикация выполняется через просмотр владельцем, merge PR и GitHub Pages согласно `CLAUDE.md`.
